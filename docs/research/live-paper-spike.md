# 公开实时行情与本地模拟：第一条持续闭环

2026-10-15，在原生历史回放验证上继续实现。使用同一个 Rust 策略、现金账户及 NautilusTrader 0.65.0 撮合引擎，以 `run(..., streaming=true)` 逐批处理新数据。没有接入 LiveNode 或 SandboxExecutionClient；这是公开 REST 行情驱动的本地模拟，不是交易所模拟账户，也不发真实订单。

## 运行及证据

在 `spikes/nautilus-trend` 下执行：

```sh
cargo test --locked -j 4
# 单次采集，包含已有日志的恢复：
cargo run --locked -j 4 -- --paper --once
# 每 60 秒采集，前台运行；Ctrl-C 停止，重跑同一命令恢复：
cargo run --locked -j 4 -- --paper
```

2026-10-15 首次真实请求得到 20 根已完成小时 K 线、1 个空仓信号和 0 笔成交。实际退出后再次启动，输入批次从 1 增至 2，信号仍为 1，成交仍为 0，未重复产生历史信号。首次收盘价 80892.93，SMA20 为 81753.1535，因此空仓符合策略规则。初始模拟现金 1000 USDT；不是人民币预算的兑换或真实分配。

最初启动了本机后台采集进程，随后短暂验证 launchd 自动恢复。用户选择提前采用 GPUI 常驻程序，现已移除 launchd，使用 [M3 GUI](../../apps/m3-desktop/README.md) 管理子进程；以 `gui-status.json` 和 `status.json` 及真实进程为准，旧 `process.pid` 不再是进程事实来源。

四个测试覆盖历史成交时序及手续费、未完成 K 线和缺口、分批输入与重建结果一致、重复 K 线拒绝、现金与买入持有对照的费用计算、日志残尾恢复和同目录进程互斥。合成行情实际触发买卖各一次；本次真实行情的空仓结果不构成实时成交充分验证。

## 数据与恢复规则

- 首次读取最近 21 根小时 K 线，只保留请求前服务器时间已经完成的部分，至少 20 根预热。之后按上一根已完成 K 线增量请求。
- 每批依次读取服务器时间、K 线、最佳买卖报价、服务器时间。请求耗时和两次服务器时间差均不得超过 10 秒。bookTicker 本身没有交易所时间戳，记录的是响应后服务器时间，不能据此证明盘口精确新鲜度。
- 校验字段、正价格、OHLC 关系、小时对齐、连续时间、已完成标记对应的时间边界、报价和可见数量。数据无效或网络错误时不推进账户，写状态、保留最后成功时间，5 秒起退避至最多 60 秒继续请求；连续失败计数可用于后续摘要。
- `inputs.jsonl` 每批先写入并同步磁盘，再处理。重启重放同一协议的全部已提交批次重建账户，摘要原子替换。文件尾部不完整行备份为 `.torn` 后移除；完整行损坏则退出，不能静默跳过。
- 同一目录使用操作系统文件锁防止两个进程同时写入。进程退出锁自动释放。
- 断线期间补回已完成 K 线，按本次接收时间更新指标，只在当前报价模拟成交；不补造停机期间的历史交易。超过 1000 根缺口暂不自动分页，会拒绝不完整数据并记录错误。
- 本地写入、已提交日志或引擎状态出错会退出，避免带着不可信状态继续。GUI 可恢复意外退出的模拟子进程；GUI 自身退出或系统休眠仍会中断采集，下一次打开从日志恢复。

## 账户与对照

同一原生策略按完成小时 K 线收盘价是否高于 SMA20，选择持有固定 0.001 BTC 或空仓。报价使用观测买卖价再各加 5bp 不利滑点；每侧费用 10bp。仅当可见两侧数量均足够时接受报价；不模拟盘口队列、部分成交或冲击。

`summary.json` 给出现金、BTC、估算清算净值、信号和成交。清算净值使用当前模拟卖价扣预计卖出费用，不自动平仓。

对照组为一直持有现金 1000 USDT，以及首次观测时买入同样 0.001 BTC、其余持有现金的基准；后者使用同样费用和滑点，当前按卖出后价值估算。它不是全仓买入持有，避免不同仓位规模被误当作策略效果。

## 明确边界

已实现 GPUI 面板和子进程管理，并安排当前线程每小时检查、24 小时中检、48 小时复盘。尚未完成持续运行验收、断网故障注入、成本敏感性、独立样本评估或 Alan 自动研究集成。详见[验证计划](paper-soak-validation.md)。日志全量重放适用于这个短实验，扩大规模时再考虑检查点；不提前建立存储平台。

模拟成交假设及固定参数尚不支持盈利结论、参数优选或实盘决策。下一次复盘先检查数据连续性、恢复记录与信号／成交因果，再讨论收益。
