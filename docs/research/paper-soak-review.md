# 首次 GUI + CLI 模拟运行复盘

本次完成了按规则买入、卖出、记录和独立对账的闭环，但**没有通过连续 48 小时运行验收，也没有证据证明策略有长期盈利优势**。电脑低电量休眠造成约 11 小时 17 分钟缺口；醒来后程序自行恢复。原窗口内有两轮完整买卖，另有一笔买入仍持仓，按最后可用报价估算卖出后，1000 USDT 模拟账户剩约 998.76 USDT。

- 终检：2026-10-17 17:06:13.257，为终点后的首次定时检查。截止之后的 50 批观测单独统计，不计入本次 48 小时结果。

## 独立核验与可复查证据

终检用独立的 Python Decimal 一次性研究审计，按原始输入从头计算每根 SMA、每批目标仓位、应发生的全部成交、手续费、余额与两个基准。审计不调用交易程序的计算函数，不请求外部行情，不控制进程，不成为 Rust 运行依赖。

结果逐项匹配当前摘要以及正式窗口每批 `batch_completed` 的信号、成交、账户和基准：

- 原始观测时间严格递增，报价与深度有效，完成 K 线时间和 OHLC 校验通过，小时 K 线没有重复或断号；其中包含醒来后读回的历史 K 线，不能据此宣称实时采集无缺口。
- 全部应发生的 5 笔成交与日志一致，不只检查已有成交是否合法；无漏掉的目标仓位变化、重复成交、空头、杠杆或执行错误。
- 窗口有 2146 个批次完成事件，批次号唯一且覆盖全部窗口输入。当前样本的日志完整，不据此宣称跨文件写入在所有崩溃情形下都恰好一次。
- 冻结源文件、两个二进制的 SHA-256 与 `validation.json` 相同；窗口前已有输入前缀未修改。
- CLI 返回的 PID 与真实进程命令匹配，终检时新鲜度正常。Agent 全程使用 CLI 和结构化文件完成运行核验。

本地证据目录为 `spikes/nautilus-trend/artifacts/paper/`：

- `inputs.jsonl`、`engine-events.jsonl`、`gui-events.jsonl`：输入与过程证据；`validation-observations.jsonl`：逐次检查及终检追加记录。

## 结论和下一条最小实验

**工程结论：** 已有观测中的采集校验、规则执行、模拟记账、独立对账与醒来后恢复工作正常；连续 48 小时采集不通过。GUI 常驻不能使休眠电脑继续采集，缺口也说明小时级 Agent 检查不能保证离线期间即时干预。

**研究结论：** 本段两轮完成交易均亏损，另有一笔未平仓。没有显示超过现金或同仓位买入持有的优势。两轮交易、一个短窗口及中间缺失的实时输入，不足以判定长期期望、证明风险更低、挑选均线参数，或宣告所有趋势策略无效。不计算据此没有意义的年化收益或夏普比率。

下一条建议实验是先解决主机供电与休眠边界，使用用户可见、可控制的 GUI 运行方式，再单独开一个规则不变的连续采集验收窗口。复用现有日志和对账，不扩建策略平台、不改参数找好看的曲线。这是建议，**本次没有自动开启新窗口、调整电源设置或重新安装 launchd**。后续检验收益优势应另行预先固定样本外数据与成本规则，避免用这次已看过的结果反复选参。

本次定时验证到此结束，按约暂停 heartbeat `m3`；GUI 模拟程序保留给用户查看和决定是否关闭，未强制卖出最后的持仓。未进行真实成交可得性、部分成交或实盘风控验收，短期模拟结果不能作为实盘上线依据。
