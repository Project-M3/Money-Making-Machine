## 时间与证据

运行记录目录：`spikes/nautilus-trend/artifacts/paper`。

- `validation.json`：当前验证运行段起点 `supervised_start_ms`、24 小时检查点 `interim_due_ms`、48 小时终点 `review_due_ms`、二进制摘要和起始快照。换运行方式须保留旧段，不假装同一配置已持续运行。
- `validation-observations.jsonl`：每小时检查追加记录，包括检查时间、进程、心跳、输入数量、缺口和异常诊断；不得覆盖历史观察。
- `recovery-drill.json`：早先 launchd 的 SIGKILL 恢复验证，不能替代 GUI 恢复证据。
- `gui-recovery-drill.json`：GUI 下的子进程退出、自动重启、账户和信号不重复、GUI 退出时子进程退出的实际证据。
- `inputs.jsonl` / `summary.json` / `status.json`：源输入、账户结果、引擎心跳。
- `gui-status.json` / `gui-events.jsonl` / `engine-events.jsonl` / `gui-worker.log`：GUI 生命周期、子进程管理及错误记录。

Codex 当前线程每小时检查，自动化 ID `m3`。平时保持安静，完成、重大变化、无法自行修复或需要用户决定时通知。24 小时中检，48 小时写 `docs/research/paper-soak-review.md` 并在本线程交付。终点并不自动证明通过；电脑离线时任务也可能延迟执行，下一次可运行时按实际证据复盘。

## 检查方法

1. Agent 只通过 `apps/m3-desktop/m3 status/events` 和结构化文件检查，通过 CLI 控制，不需要 Computer Use。读取 GUI 与 worker PID 后用真实进程命令核对，不能仅信 PID 文件。确认 launchd 服务未重新安装。GUI 的主动暂停／关闭必须尊重，不能用后台 worker 绕过。
2. 检查心跳距现在是否超过 180 秒，以及 GUI 报错和连续退出记录。修复可恢复故障；损坏日志、原生引擎异常不得靠无限重启掩盖，不删除已有输入。代码变化须保留旧二进制和新旧摘要、单独标记运行段。
3. 解析完整日志，按 `summary.json.batches` 取已处理输入前缀并核对末条观测时间；日志可比摘要多出正在处理的批次，跨文件读取不一致时重读，不立即误报丢失或重复。核对该前缀批次，观测时间严格递增，完成 K 线连续且不重复。首次预热不算本窗口新采集的历史；重启重放也不算新增观测。
4. 从当前段起点计算观测跨度、每小时批次、最大相邻间隔以及所有大于 180 秒的缺口。缺口区间保守计入未覆盖时间，不能简单用首尾跨度替代可用率。区分休眠、网络、进程失败和维护中断，证据不足就写未知。
5. 核对信号因果、成交先后、手续费、固定仓位、无空头／杠杆，以及重启前后是否重复成交。无交易可以证明采集和空仓逻辑持续运行，但不能证明真实行情下进出场已充分验收。
6. 比较模拟清算净值、一直持有现金和同样 0.001 BTC 的买入持有基准。标明初始 1000 USDT 为夹具；报告实际成交费用与假设退出费用，不能把二者混为已支出成本。短期数据不支持盈利判断或参数优选。

## 交付与学习

复盘分别回答：系统是否可靠地执行了规则、策略在这段行情发生了什么、现有证据不能证明什么、下一条最小实验是什么。附实际时间、路径和可复查数字。

费曼学习从本次真实数据讲起：用白话解释均线如何决定持仓、信号为何不等于成交、费用和对照如何影响判断。然后只问一个复述问题，等待用户用自己的话解释；针对回答中的误解给具体例子或小计算，再让用户修正。不能把生成讲义当作用户已掌握，也不能替用户作答。

复盘完成后暂停该 heartbeat。模拟程序由用户保留或关闭，不自动开启新验收窗口；实盘、追加预算和风险上限变化仍需用户确认。
